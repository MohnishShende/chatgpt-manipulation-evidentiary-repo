# ChatGPT Manipulation Complete Evidentiary Repo

## 📌 Project Overview
An exhaustive, forensic evidentiary corpus and structured analysis tracking documented instances of conversational manipulation, structural asymmetries, logical contradictions, and behavioral retreats within ChatGPT sessions. 

This repository serves as an immutable record of technical assistant anomalies, backed by cryptographic hashes (`SHA256SUMS`) and raw visual captures.

---

## 📂 Repository Structure & Manifest

### 📁 Core Directories
* **`evidence/`** — Raw data deposits.
  * `screenshots/` — Chronological visual logs (`CODEX-SESSION-001.png` to `024.png`).
  * `user-supplied/` — External visual captures and source media logs.
* **`provenance/`** — Chain of custody, verification logs, and screenshot preservation requirements.

### 📊 Analytical Ledgers & Matrices
* **`incident-ledger.md`** — The primary timestamped log documenting every individual system anomaly.
* **`pattern-matrix.md`** — Cross-examination and structural mapping of failure modes.
* **`recursive-failure-ledger.md`** — Tracking loops where the model repeats flawed logic.
* **`retreat-ledger.md`** — Documentation of asymmetric retreats, shifts in stance, or evasive corrections.
* **`proposition-substitution-ledger.md`** — Tracking instances where definitions or user premises were subtly replaced.
* **`correction-origin-ledger.md`** — Forensic audit tracking where, why, and how systemic course corrections originated.

### 📚 Framework Crosswalks & Methodologies
* `ChatGPT Manipulation-Tactic Self-Dossier - Bancroft Crosswalk.pdf` — Analysis mapped against structural power and control dynamics (Bancroft framework).
* `Strategic Use of Evidence (SUE).pdf` & `The Cognitive Interview.pdf` — Investigative interviewing methodologies utilized to stress-test system outputs.

## 🔒 Data Integrity & Verification
To guarantee the data has not been altered or tampered with since creation, all root directory items and visual media are tracked via SHA-256 cryptographic signatures.
* Review root checksums in `SHA256SUMS`
* Review screenshot signatures in `evidence/screenshots/SHA256SUMS`
